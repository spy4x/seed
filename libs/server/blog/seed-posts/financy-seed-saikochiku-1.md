SaaSスターターの上に本物のプロダクトを作り、しかもスターターのアップデートを受け取り続けることはできるのか。いま、まさにそれを[Financy](https://github.com/spy4x/financy)でやっています。Financyは個人や家族のための、無料でオープンソース（AGPL-3.0）の家計管理アプリです。2026年11月3日にSeedのコピーとして作り直しを始め、11月4日には最初のSeedの変更を取り込みました。19コミット、616ファイル、コンフリクトはゼロです。このシリーズでは、作り直しを進行形で追いかけます。

対象は、SaaSスターターを選んでいて、デモ以外で実際に使われている例を見たい開発者と、Financyに興味がある方です。ここに書くことはすべて公開情報で、数字はどれもGitHub上の2つのリポジトリから取っており、gitで自分で数え直せます。

## なぜ直すのではなく作り直すのか

初代Financyは2025年4月に始まり、157コミットまで育ちました。複数通貨の口座を管理し、通貨間の換算をし、E2Eテストもありました。一方で、もう信用できないコードも抱えていました。多くは当時のAIモデルを使って急いで書いたもので、目指すプロダクトにするには、構造も状態管理も同期も結局作り直す必要がありました。

答えのもう半分は、Financyに足りなかったものです。家庭向けの家計管理アプリには、二要素認証つきのログイン、ロールつきのグループ、全端末へのリアルタイム反映、オフラインで動くアプリ、管理画面、公開サイトが必要です。これはお金の話ではなく、どのSaaSにも要る配管です。そして私はちょうど10月いっぱいをかけて、その大半をSeedに作り込んだところでした（[10月に入ったもの](/blog/whats-new-in-seed-october-2026)、英語）。Financyの中でもう一度書くのは、Seedが防ぐために存在する失敗そのものです。

そこで旧Financyは[`legacy`](https://github.com/spy4x/financy/tree/legacy)ブランチに凍結しました。Financyが**何を**するか（機能、お金のルール、境界ケース）を確かめる資料であって、**どう**作るかの資料ではありません。ヘルパー関数ひとつ移植しません。旧版から取ったお金のルールは仮説として扱い、まずテストにしてから新しいコードを書きます。

## FinancyはどうやってSeedから始まったのか

プルリクエスト1つ、[financy#83](https://github.com/spy4x/financy/pull/83)です。Seedのファイルに、コピーをFinancyにする19ファイルを足しました。この数は、Financyの最初のコミットと、そこに記録されたSeedのコミットを比べて数えました。

```sh
git fetch https://github.com/spy4x/seed main
git diff --stat "$(git show 3d267c6f:.seed/commit)" 3d267c6f
```

19ファイルの中身は次のとおりです。AGPL-3.0のライセンス（SeedのMIT表記は別ファイルに残す）、アプリがまだ使えないと正直に書いたREADME、Financyの`AGENTS.md`（関わるエージェントと人が従うルール）、プロダクト資料、Financyのタグが決してSeedのイメージを上書きしないようにするリリースパイプラインのイメージ名、削除したSeedの暗号化サーバー設定4つ、そして同期を可能にする2つのファイルです。

この2つが仕掛けのすべてです。`.seed/commit`にはコピーが対応するSeedのコミットを、`.seed/skip`にはFinancyが変更を受け取らないSeedのパス（READMEなど）を書きます。同期とは、そのコミットからSeedの現在の`main`までの`git diff`を、3-wayマージで適用することです。手順の全体は[Start a product from Seed and keep getting its updates](/blog/start-a-product-from-seed-and-keep-its-updates)（英語）にあります。この記事は、それを実際にやってみたらどうなったかの記録です。

## 最初の同期は本当にうまくいったのか

はい。しかも、わざと小さな罠を仕掛けたうえでです。同期の前に、FinancyはすでにSeedのファイルを変えていました。[financy#123](https://github.com/spy4x/financy/pull/123)で、名前、財布のアイコン、Seedの紫に代わる独自の青を、32ファイルにわたって入れています。手つかずのコピーでしか動かない同期では、何の証明にもなりません。

続いて[financy#127](https://github.com/spy4x/financy/pull/127)で、Seedを`ec61062b`から`d9641f03`まで進めました。Seedのプルリクエスト19件、変更ファイル616個を、`git apply --3way`はコンフリクトなしで適用しました。届いたものの一部です。

- メールで届くコードでのログイン
- 月額の横に並ぶ年額料金
- グループ全体のタイムゾーン
- Denoに加えてNodeとBunでも動くAPIとワーカー
- プロダクトの変更履歴をどこから始めるかの設定

同期では、プロダクト側が手で行う手順も1つ見つかりました。Seedには、Seed自身のリポジトリ用ルールである`AGENTS.seed.md`が追加されたばかりでした。Financyはこれを削除して`.seed/skip`に加え、以後の同期で戻ってこないようにしました。同期後、FinancyとSeedの差は59ファイルで、そのすべてがFinancyが意図して変えたファイルです。

## FinancyではなくSeedに入れるものは何か

どのSaaSにも必要なものすべてです。順番はFinancyの`AGENTS.md`が決めています。どのプロジェクトでも使えるコードは共有ライブラリ`@spy4x/*`へ、Seed上のどのプロダクトにも必要なコードはSeedへ、そしてお金のプロダクトにだけ必要なもの（口座、取引、予算、為替レート）だけがFinancyに残ります。「あとで移す」ローカルの仮実装は作りません。「あとで」こそ、フォークが離れていく原因だからです。

上のリストのうち3つが、まさにそれです。Financyには年額課金が必要で、家庭の「1か月」は全員で同じタイムゾーンでなければならず、変更履歴が旧アプリの何年分ものコミットから始まってはいけません。どれもお金の話ではないので、それぞれSeedで作り、同期でFinancyに届きました。11月3日と4日に、Financyに触れたSeedの新しいissueが31件立ち、11月5日までにそのうち8件がクローズされました。

作り直しは、私自身の手順の穴も見つけました。プロダクトがSeedのサイトから取り除くもののリストはいくつかのファイルを漏らしていましたし、手順1はSeedの最新コミットを記録していました。最新コミットはコピーより新しいことがあり、その場合、最初の同期は間のコミットを黙って飛ばしてしまいます。どちらもSeedで修正済みで（[seed#811](https://github.com/spy4x/seed/pull/811)）、[ガイド](/ja/docs/products)には、自分のファイルと一致するコミットの見つけ方が書いてあります。この修正は私よりあなたの役に立ちます。次にSeedで作られるプロダクトは、もうこの穴に落ちません。

## まだできていないことは何か

ほとんど全部です。これを書いている時点のFinancyは、Financyの名前とライセンスと色をまとったSeedです。口座、取引、予算の画面はまだないので、今は使わないでください。名前さえ決まっていません。[financy#126](https://github.com/spy4x/financy/issues/126)で、ローンチ前に名前を変えるかどうかを検討しています。

計画は公開しています。[Financyのissue](https://github.com/spy4x/financy/issues)は、土台からローンチ、そしてその後までの7つのマイルストーンに分かれています。そこで見つかったSeedの穴はSeedで直すので、このシリーズでは両方の側、つまりFinancyが何を必要とし、Seedがそこから何を学んだかをお見せしていきます。

## 続きを追いかける

[FinancyのリポジトリをWatch](https://github.com/spy4x/financy)すると、プルリクエストが入るたびに見られます。このブログを購読すれば、第2回がメールで届きます。自分のプロダクトを始めようとしているなら、[ガイド](/ja/docs/products)はFinancyが従っているものと同じです。もし途中の手順でつまずいたら、[issueを開いてください](https://github.com/spy4x/seed/issues)。手順に1行足りないということです。
