Seed, бесплатный шаблон для SaaS, теперь работает на Deno, Node.js и Bun. API, фоновый воркер,
миграция базы и публичный сайт запускаются на каждом из них без изменений в коде, а CI поднимает API,
воркер и сайт на всех трёх для каждого pull request. Рантайм серверов продукта выбирает одна строка в
env-файле; если её нет, всё остаётся на Deno.

Пост для двух читателей. Первый выбирает стартовый шаблон и не хочет ставить продукт на один
рантайм. Второй уже ведёт продукт на Seed и скоро заберёт это изменение очередной синхронизацией.
Каждый раздел отвечает на одно действие. Как шёл сам переезд, с ошибками, я описал
[в своём блоге](https://antonshubin.com/blog/migrate-from-deno-to-node-and-bun) (на английском).

## Как начать новый продукт на своём рантайме?

В быстром старте README теперь отдельный раздел на каждый рантайм:
[Node](https://github.com/spy4x/seed#node), [Bun](https://github.com/spy4x/seed#bun) и
[Deno](https://github.com/spy4x/seed#deno). Нужны Docker и один из трёх. Для Node:

```sh
npm install -g deno
gh repo create my-product --template spy4x/seed --private --clone
cd my-product
npm run init
npm run dev
```

Да, первая строка ставит Deno. Уходить с Deno, начиная с установки Deno, смешнее, чем хотелось бы,
но собственные задачи Seed пока работают на нём (об этом ниже), а пакет `deno` в npm означает, что
машине с одним Node больше ничего не нужно. Для Bun первая строка — `bun add -g deno`, а последние
две — `bun run init` и `bun run dev`. Строка с `gh` необязательна: кнопка «Use this template» на
GitHub и обычный clone делают то же самое.

Так вы получите весь стек в Docker на Deno. Чтобы и серверы продукта работали на Node или Bun,
добавьте одну строку в `infra/envs/.env` до `dev`:

```sh
APP_RUNTIME=node   # или bun; deno, пустое значение или отсутствие строки оставляет Deno
```

## Что работает на Node или Bun и чем это отличается?

С `APP_RUNTIME=node` или `bun` API, воркер, миграция и сайт работают на Node 26 или Bun 1.4, каждый
из своего Docker-образа. Порты, переменные окружения и порядок запуска сервисов не меняются. SPA и
админка — статические файлы, им всё равно. Полный список — в
[разделе документации о рантайме](/ru/docs/apps#runtime).

Три отличия от Deno, о которых стоит знать заранее:

- **Нет режима наблюдения.** Сборка попадает в образ, поэтому на Node или Bun изменение кода видно
  только после пересборки, и в разработке тоже. Разработка с горячей перезагрузкой остаётся на Deno.
- **У воркера нет разрешений рантайма.** На Deno воркер может читать и писать только свою папку с
  картинками и запускать только `vips`. У Node и Bun таких ограничений нет, там воркер ограничен лишь
  контейнером и пользователем без root.
- **Это ваш выбор, а не значение по умолчанию.** Без строки, с пустой строкой или с `deno` всё
  остаётся на Deno.

## У меня уже есть продукт на Seed. Что делать?

Заберите изменение как обычно, по [руководству для продуктов](/ru/docs/products): получите Seed,
примените патч и запишите коммит:

```sh
git fetch https://github.com/spy4x/seed main
git diff --binary "$(cat .seed/commit)" FETCH_HEAD -- . ':!AGENTS.md' $(sed '/^$/d; s/^/:!/' .seed/skip) | git apply --3way && git rev-parse FETCH_HEAD > .seed/commit
```

Потом запустите `deno task check` и только после этого открывайте pull request. Я прогнал эту
синхронизацию на копии Seed из момента прямо перед переездом, и патч лёг без единого конфликта. В
вашем продукте конфликты возможны там, где вы намеренно меняли файлы Seed: оставляйте свою версию,
как советует руководство.

Синхронизация добавит Docker-образы для Node и Bun, файлы Compose, которые на них переключают, и
`package.json` в корне. Рантайм она не меняет. Когда захотите переехать, поставьте
`APP_RUNTIME=node` (или `bun`) в `infra/envs/.env` и пересоберите образы:

```sh
deno task compose up -d --build
```

На сервере добавьте ту же строку в env-файл сервера и деплойте как обычно
([обновления](/ru/docs/deploy-updates)): каждый деплой собирает образы, которые указывает эта строка.

## Что поменялось на публичном сайте?

Сайт больше не работает на Fresh. Теперь под ним
[`@spy4x/preact-server`](https://jsr.io/@spy4x/preact-server) — маленький открытый слой, который
повторяет маршруты, страницы и острова Fresh 2, поэтому код сайта почти не изменился. Я сравнил
ответы всех маршрутов на обеих сборках: 419 из 423 совпали. Четыре расхождения — это дата изменения и
ETag одного видео и кривой адрес, на который раньше приходила голая ошибка, а теперь приходит
страница 404 самого сайта.

Страницы ещё и полегчали. JavaScript на страницу после gzip, замер Lighthouse в мобильном режиме:

| Страница              | Новый слой | Fresh   |
| --------------------- | ---------- | ------- |
| Главная               | 24.0 KB    | 32.1 KB |
| Пост блога с островом | 29.9 KB    | 38.0 KB |
| Документация          | 8.6 KB     | 19.4 KB |

На посте с интерактивным ползунком страница блокирует ввод на 5 мс против 48 мс на Fresh. Моя первая
версия слоя там проигрывала Fresh, и CI этого не заметил; как я это нашёл — в
[полной истории](https://antonshubin.com/blog/migrate-from-deno-to-node-and-bun).

Если вы меняли сайт своего продукта, после синхронизации у вас могут остаться файлы с импортами из
Fresh. Найдите их из корня репозитория:

```sh
grep -rlE 'from "fresh' apps/mpa
```

Замените каждый импорт на `@spy4x/preact-server` (включая `fresh/runtime`), а `FreshContext`
переименуйте в `Context`. Папка сборки теперь `dist`, а не `_fresh`. Встроенных скриптов на страницах
больше нет, поэтому заголовкам безопасности не нужен nonce на каждый запрос. Слой — первая версия:
что в нём есть и чего нет, написано в
[его документации](https://github.com/spy4x/seed/blob/main/docs/website-server.md).

## Что пока требует Deno?

Инструменты: форматирование, линтер, проверка типов, тесты и скрипты за `deno task`. `package.json` в
корне передаёт основные задачи в Deno, так что `npm run test` и `bun run dev` тоже работают. Тесты
остаются на тест-раннере Deno. Изменится ли это, решит пересмотр, назначенный на 10 января 2027 года
([политика рантаймов](https://github.com/spy4x/seed/blob/main/docs/runtime-policy.md)). Рантайм, на
котором работают ваши пользователи, от этого к Deno не привязан.

## Почему Seed отвязался от Deno?

9 октября 2026 года команда Deno [объявила](https://deno.com/blog/cloudflare) ещё год исправлений
ошибок и уязвимостей, после чего прекращает собственную разработку. Deno остаётся открытым, и он мне
по-прежнему нравится. Но шаблон, на котором строят бизнес, не должен ставить ваш продукт на планы
одного рантайма, мои в том числе. Seed и так был построен на веб-стандартах (Fetch, Web Crypto,
WebSocket, ES-модули), поэтому сложным оказалось другое: отдача файлов, типы Deno в публичных
сигнатурах и слой сайта, а не переписывание.

Попробуйте [быстрый старт](https://github.com/spy4x/seed#quick-start) на том рантайме, которым уже
пользуетесь. Если какой-то шаг не сработает,
[откройте issue](https://github.com/spy4x/seed/issues) с тем, что запускали, и я исправлю.
