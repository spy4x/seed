Seed، قالب SaaS المجاني ومفتوح المصدر، يعمل الآن على Deno وNode.js وBun. الواجهة البرمجية (API)
والعامل الخلفي وترحيل قاعدة البيانات والموقع العام تبدأ على كل واحدة منها دون تغيير سطر من الكود،
ونظام التكامل المستمر يشغّل الواجهة البرمجية والعامل والموقع على الثلاثة في كل طلب دمج. سطر واحد
في ملف البيئة يختار بيئة تشغيل خوادم منتجك، وإن لم تضعه يبقى كل شيء على Deno.

هذا المقال لقارئين: من يختار قالبًا لمشروعه ولا يريد أن يربط منتجه ببيئة تشغيل واحدة، ومن لديه
منتج مبني على Seed وسيصله هذا التغيير في المزامنة القادمة. كل قسم يجيب عن مهمة واحدة. أما قصة
الانتقال نفسها، بأخطائها، فهي
[في مدونتي](https://antonshubin.com/blog/migrate-from-deno-to-node-and-bun) (بالإنجليزية).

## كيف أبدأ منتجًا جديدًا على بيئة التشغيل التي أستخدمها؟

صار في دليل البدء السريع في README قسم لكل بيئة تشغيل:
[Node](https://github.com/spy4x/seed#node) و[Bun](https://github.com/spy4x/seed#bun)
و[Deno](https://github.com/spy4x/seed#deno). تحتاج إلى Docker وواحدة من الثلاث. على Node:

```sh
npm install -g deno
gh repo create my-product --template spy4x/seed --private --clone
cd my-product
npm run init
npm run dev
```

نعم، السطر الأول يثبّت Deno. أن تترك Deno بتثبيت Deno أمر مضحك أكثر مما أحب، لكن مهام Seed
نفسها لا تزال تعمل عليه (التفاصيل أدناه)، وحزمة `deno` على npm تعني أن جهازًا عليه Node وحده لا
يحتاج إلى شيء آخر. على Bun يصبح السطر الأول `bun add -g deno`، والسطران الأخيران `bun run init`
و`bun run dev`. سطر `gh` اختياري: زر "Use this template" في GitHub ثم clone يفعلان الشيء نفسه.

بهذا تحصل على المنظومة كاملة داخل Docker على Deno. ولكي تعمل خوادم المنتج نفسها على Node أو Bun،
أضف سطرًا واحدًا إلى `infra/envs/.env` قبل `dev`:

```sh
APP_RUNTIME=node   # أو bun؛ القيمة deno أو قيمة فارغة أو غياب السطر يُبقي Deno
```

## ما الذي يعمل على Node أو Bun، وما الذي يختلف هناك؟

مع `APP_RUNTIME=node` أو `bun` تعمل الواجهة البرمجية والعامل والترحيل والموقع على Node 26 أو
Bun 1.4، كل منها من صورة Docker خاصة به. المنافذ ومتغيرات البيئة وترتيب تشغيل الخدمات لا تتغير.
تطبيق الصفحة الواحدة (SPA) ولوحة الإدارة ملفات ثابتة، فلا يعنيهما الأمر. التفاصيل الكاملة في
[قسم بيئة التشغيل في التوثيق](/ar/docs/apps#runtime).

ثلاثة فروق عن Deno يحسن أن تعرفها قبل الانتقال:

- **لا وضع مراقبة.** يُحزَم الكود داخل الصورة، فعلى Node أو Bun لا يظهر أي تعديل إلا بعد إعادة
  البناء، حتى أثناء التطوير. التطوير مع إعادة التحميل الفوري يبقى على Deno.
- **لا أذونات بيئة تشغيل للعامل.** على Deno لا يستطيع العامل القراءة والكتابة إلا في مجلد صوره، ولا
  يشغّل إلا `vips`. أما Node وBun فلا حدود من هذا النوع فيهما، وهناك لا يقيّد العامل إلا حاويته
  ومستخدمه غير الجذري.
- **القرار لك.** بلا سطر، أو بسطر فارغ، أو بالقيمة `deno`، يبقى كل شيء على Deno.

## لديّ منتج يعمل على Seed. ماذا أفعل؟

خذ التغيير كالمعتاد، كما يشرح [دليل المنتجات](/ar/docs/products): اجلب Seed، وطبّق الرقعة، وسجّل
الالتزام:

```sh
git fetch https://github.com/spy4x/seed main
git diff --binary "$(cat .seed/commit)" FETCH_HEAD -- . ':!AGENTS.md' $(sed '/^$/d; s/^/:!/' .seed/skip) | git apply --3way && git rev-parse FETCH_HEAD > .seed/commit
```

ثم شغّل `deno task check` قبل أن تفتح طلب الدمج. جرّبت هذه المزامنة على نسخة من Seed من قبيل
تغيير بيئة التشغيل مباشرة، فطُبّقت الرقعة دون أي تعارض. قد يظهر تعارض في منتجك حيث غيّرت ملفات
Seed عن قصد: احتفظ بنسختك هناك، كما يقول الدليل.

تضيف المزامنة صور Docker الخاصة بـ Node وBun، وملفات Compose التي تنتقل إليها، وملف `package.json`
في جذر المستودع. لكنها لا تغيّر بيئة التشغيل التي تستخدمها. حين تريد الانتقال، ضع
`APP_RUNTIME=node` (أو `bun`) في `infra/envs/.env` وأعد بناء الصور:

```sh
deno task compose up -d --build
```

وعلى الخادم، ضع السطر نفسه في ملف البيئة الخاص به وانشر كالمعتاد
([التحديثات](/ar/docs/deploy-updates)): كل نشر يبني الصور التي يحددها ذلك السطر.

## ما الذي تغيّر في الموقع العام؟

لم يعد الموقع يعمل على Fresh، بل على
[`@spy4x/preact-server`](https://jsr.io/@spy4x/preact-server)، وهي طبقة صغيرة مفتوحة المصدر تنسخ
مسارات Fresh 2 وصفحاته وجزره، لذلك بالكاد تغيّر كود الموقع. قارنت كل المسارات على النسختين: 419 من
423 استجابة جاءت متطابقة. الفروق الأربعة هي تاريخ تعديل فيديو واحد ووسم ETag الخاص به، وعنوان
مشوّه كان يتلقى خطأً عاريًا وصار يتلقى صفحة 404 الخاصة بالموقع.

وصارت الصفحات أخف أيضًا. حجم JavaScript لكل صفحة بعد الضغط بـ gzip، مقيسًا بـ Lighthouse في وضع
الجوال:

| الصفحة                 | الطبقة الجديدة | Fresh   |
| ---------------------- | -------------- | ------- |
| الرئيسية               | 24.0 KB        | 32.1 KB |
| مقال في المدونة بجزيرة | 29.9 KB        | 38.0 KB |
| التوثيق                | 8.6 KB         | 19.4 KB |

في المقال الذي فيه شريط تمرير تفاعلي، تحجب الصفحة الإدخال 5 ميلي ثانية، مقابل 48 ميلي ثانية على
Fresh. كانت نسختي الأولى من الطبقة أبطأ من Fresh في هذا الموضع بالذات، ولم ينتبه التكامل المستمر؛
كيف اكتشفت ذلك تجده في
[القصة الكاملة](https://antonshubin.com/blog/migrate-from-deno-to-node-and-bun).

إن كنت عدّلت موقع منتجك، فقد تبقى بعد المزامنة ملفات لا تزال تستورد من Fresh. ابحث عنها من جذر
المستودع:

```sh
grep -rlE 'from "fresh' apps/mpa
```

وجّه كل استيراد إلى `@spy4x/preact-server` (ومنها `fresh/runtime`)، وغيّر اسم `FreshContext` إلى
`Context`. مجلد البناء صار `dist` بدل `_fresh`. ولم تعد في الصفحات سكربتات مضمّنة، فلا تحتاج ترويسات
الأمان إلى قيمة nonce لكل طلب. الطبقة نسخة أولى: ما تقدمه وما تتركه موجود في
[توثيقها](https://github.com/spy4x/seed/blob/main/docs/website-server.md).

## ما الذي لا يزال يحتاج إلى Deno؟

أدوات العمل: التنسيق والفحص والتحقق من الأنواع والاختبارات والسكربتات التي خلف `deno task`. ملف
`package.json` في الجذر يمرّر المهام الشائعة إلى Deno، لذلك يعمل `npm run test` و`bun run dev`
أيضًا. وتبقى الاختبارات على مشغّل الاختبارات في Deno. أما تغيير ذلك فتقرره مراجعة موعدها 10 يناير
2027 ([سياسة بيئات التشغيل](https://github.com/spy4x/seed/blob/main/docs/runtime-policy.md)). لا شيء
من هذا يربط بـ Deno بيئة التشغيل التي يصل إليها مستخدموك.

## لماذا توقف Seed عن الاعتماد على Deno؟

في 9 أكتوبر 2026 [أعلن](https://deno.com/blog/cloudflare) فريق Deno عن سنة أخرى من إصلاحات الأخطاء
والتحديثات الأمنية، يتوقف بعدها عن تطويره بنفسه. يبقى Deno مفتوح المصدر، وما زلت أحبه. لكن القالب
الذي تبني عليه عملًا تجاريًا لا ينبغي أن يراهن بمنتجك على خطة بيئة تشغيل واحدة، ولا على خطتي أنا.
كان Seed مبنيًا أصلًا على معايير الويب (Fetch وWeb Crypto وWebSocket ووحدات ES)، فكان الصعب هو تقديم
الملفات، وأنواع Deno في التواقيع العامة، وطبقة الموقع، لا إعادة كتابة كل شيء.

جرّب [البدء السريع](https://github.com/spy4x/seed#quick-start) على بيئة التشغيل التي تستخدمها أصلًا.
وإن فشلت خطوة، [افتح issue](https://github.com/spy4x/seed/issues) بما شغّلته، وسأصلحها.
